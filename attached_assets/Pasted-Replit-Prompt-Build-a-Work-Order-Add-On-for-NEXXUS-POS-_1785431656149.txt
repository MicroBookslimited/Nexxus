Replit Prompt: Build a Work Order Add-On for NEXXUS POS

You are a senior full-stack SaaS engineer working inside the existing NEXXUS POS codebase.
Build a production-ready Work Order Management add-on for NEXXUS POS.
The module must help service-based businesses manage customer jobs from intake through assessment, quotation, approval, scheduling, technician assignment, parts usage, labour tracking, invoicing, payment, completion, and warranty follow-up.
The module should support businesses such as:
- POS installation and repair companies
- Security camera installers
- Access control technicians
- Computer and electronics repair shops
- Appliance repair businesses
- Automotive workshops
- Contractors
- Field service companies
- Maintenance providers
Do not create a separate application. Build this as a native NEXXUS POS module using the existing architecture, authentication, permissions, customers, products, inventory, invoicing, payments, locations, taxes, notifications, reporting, and design system.
--------------------------------------------------
1. DEVELOPMENT RULES
--------------------------------------------------
Before coding:
1. Inspect the existing NEXXUS POS repository.
2. Identify the current frontend, backend, database, authentication, state management, UI component library, validation, and API conventions.
3. Locate the existing models and services for:
   - Businesses
   - Locations
   - Users
   - Roles and permissions
   - Customers
   - Products
   - Inventory
   - Sales
   - Estimates
   - Invoices
   - Payments
   - Taxes
   - Notifications
   - Subscription plans
4. Reuse existing services and components wherever possible.
5. Do not duplicate existing functionality.
6. Do not break any current POS feature.
7. Preserve the existing NEXXUS visual design.
8. Use the existing project naming conventions and folder structure.
9. Add database migrations, validation, authorization, tests, indexes, and audit logging.
10. All records must be isolated by business_id.
11. Respect location-level access.
12. Enforce permissions on the server, not only in the frontend.
13. Do not use mock data in production workflows.
14. Use soft deletion where appropriate.
15. Make all screens responsive for desktop, tablet, and mobile.
First provide a concise implementation plan, then begin implementation in phases.
